# 프로젝트

## AWS EKS 기반 마이크로서비스 배포 및 모니터링 시스템 구축 (2025)
- 사용 서비스: AWS EKS, EC2, VPC, S3, CloudWatch, RDS, CloudFront, WAF
- 기타 기술: k6, Docker, Prometheus, Grafana, Karpenter, KEDA, Helm
- EKS on EC2 환경에서 3개의 마이크로서비스(API)를 단일 엔드포인트로 운영하고, RDS(Multi-AZ)를 연계한 고가용성 인프라를 구축했습니다.
- BottleRocket AMI를 적용해 컨테이너 Cold Start 시간을 단축하고 노드 부팅 성능을 개선했습니다.
- Prometheus, Grafana, CloudWatch 기반 모니터링·로깅 환경을 구축하고, 4xx/5xx/2xx 요청을 모니터링하며 SLO(응답시간 0.2~1초)를 만족하도록 운영했습니다.

## EKS 프로젝트 성과: 부하 테스트와 비용 최적화
- k6로 부하 테스트를 수행했고, 실제 대회에서 20만 건 이상의 트래픽에 대해 3개 API 모두 요청 처리율 99%를 달성했습니다.
- 응답 시간 0.2초 기준으로 API별 99%, 89%, 80%의 처리율을 기록하며 성능 목표를 충족했습니다.
- Karpenter, HPA, 캐싱 전략을 적용해 EC2 인스턴스 2~3대만으로 대규모 트래픽을 안정적으로 처리하고 인프라 비용을 최적화했습니다.

## EKS 프로젝트 트러블슈팅: DB 커넥션 초과 문제
- 문제: product, user API에 트래픽이 몰릴 때 애플리케이션(Pod)들이 만든 커넥션 총합이 DB의 max_connections를 초과해, 신규 커넥션이 거부되며 요청이 실패했습니다.
- 원인: Pod 오토스케일링 시 "Pod 수 × 커넥션 풀 크기"가 DB의 max_connections를 넘는 구조였습니다. 커넥션이 애플리케이션마다 독립적으로 관리되어 재사용되지 못했고, 트래픽 급증 구간에서 한도를 초과했습니다.
- 해결 1 - RDS Proxy 도입: 다수의 애플리케이션 커넥션을 소수의 DB 커넥션으로 멀티플렉싱(재사용)했습니다. 앱 쪽 커넥션 총합이 max_connections를 넘어도 Proxy가 큐잉·재사용으로 흡수해 요청 실패를 막았습니다.
- 해결 2 - 인덱스 최적화: 조회 빈도가 높은 컬럼에 인덱스를 설정해 쿼리 속도를 개선했습니다. 커넥션 점유 시간이 줄어 동시 커넥션 수요 자체가 감소했습니다.
